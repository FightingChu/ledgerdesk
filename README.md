# LedgerDesk 本地账目核查工具

LedgerDesk 将业务单中的预计净到账，与支付账单中的收款减退款逐单比较，帮助定位金额差异、单边缺失、重复业务单和重复流水。它在本机浏览器运行，使用本地 SQLite 保存批次、导入记录、文件指纹、核查结果和人工备注。

**当前状态：0.6.0 个人验证版。尚无真实客户、付费交付或生产使用记录。附带数据均为合成样例。** 本项目可以用于验证产品流程，当前状态不满足此前命题项目对真实客户或生产来源的要求。

## 启动

Windows 双击当前目录的 `start.cmd`。已安装 Python 3.10 以上即可，不需要安装第三方包、数据库服务、Node.js、域名或服务器。启动后会打开浏览器；保持终端窗口运行。已有同端口、相同版本且使用相同数据目录的 LedgerDesk 时，再次双击会打开现有页面。不同数据目录会提示冲突，请换端口；不同版本的服务需先停止；并行测试请使用各自的数据目录和端口。

也可以在项目目录的 PowerShell 中执行：

```powershell
python -m ledgerdesk --open
```

默认地址是 `http://127.0.0.1:8765`。按 Ctrl+C 停止，已提交的数据不会随窗口关闭消失。端口被其他程序占用时：

```powershell
python -m ledgerdesk --port 8766 --open
```

服务固定绑定 `127.0.0.1`，首版面向单人本机使用。界面没有远程账户或多人权限管理，不能直接当作公网服务部署。

## 第一次体验

1. 点击“创建样例批次”。系统导入附带的合成数据，生成 7 个订单分组，其中 2 个金额一致、5 个有差异。
2. 使用“待核查差异 / 全部记录 / 金额一致”和订单号搜索筛选记录。
3. 点击“查看”，核对源文件名、CSV 行号、收款和退款记录。
4. 填写处理备注。标记“已处理”时必须填写依据；人工状态不会将金额差异改成金额一致。
5. 使用上一页/下一页查看记录，点击“查看”再加载该订单源行。默认每页 50 项，可选择 25 或 100。
6. 点击“导出全部记录”或“导出当前筛选”，下载带 UTF-8 BOM 的 CSV；导出包含所有匹配记录，不限于当前页。合成样例会明确标注。

创建自己的核查批次时，分别上传业务单与支付账单，确认每个字段对应的 CSV 列，再执行核对。导入预览显示前五行；确认导入会校验整份文件。数据有错误时整份不写入，页面列出错误行。

## 输入格式和业务口径

首版处理**标准逗号分隔 CSV**，支持 UTF-8、UTF-8 BOM、GB18030。单文件不超过 5 MiB、10000 行。可以在一个批次中导入多份文件。同一批次、同一数据侧、相同原始字节的文件只导入一次，重命名文件不会绕过此检查。相同文件用不同映射再次导入会被拒绝，纠正映射或渠道别名请使用替换文件，并填写原因。

业务单格式：

```csv
order_id,amount,channel
000012,80.00,wechat
```

`amount` 是该订单**预期收到的净额**：扣除预计退款，不扣支付手续费。首版只接受非负数；一组 `(channel, order_id)` 应只有一行业务单。订单号按字符串处理，保留前导零。

支付账单格式：

```csv
order_id,transaction_id,amount,event_type,channel
000012,P0001,100.00,sale,wechat
000012,R0001,20.00,refund,wechat
```

`sale` 表示收款，`refund` 表示退款，两者金额都填写正数。兼容中文“收款 / 支付 / 退款”。每个渠道内的 `transaction_id` 应唯一，退款须使用不同的退款流水号。同订单多次合法收款或退款允许合并。

核查按 `(channel, order_id)` 精确匹配，渠道和订单号去除首尾空白后保留大小写。未配置别名时，`wechat` 和 `微信` 是不同渠道值；导入时可以明确配置“微信 = wechat”。计算为：

```text
账单净额 = 该订单收款合计 - 退款合计
差额 = 账单净额 - 业务单预计净到账
```

所有金额仅接受人民币元，最多两位小数，内部转成整数分计算。不接受负数输入、千分位、科学计数法和超过 100 亿元的单行金额。零金额保留。自动识别 `currency`、`currency_code`（不区分大小写）及 `币种`、`货币`、`货币种类` 列，只接受 CNY、RMB、人民币（英文值不区分大小写）。多个币种列须在每一行表达相同币种，CNY 与 RMB 视为等价；空白、未知币种、非人民币或冲突列会拒绝整份导入。没有币种列时按本工具约定视为人民币，不自动汇兑。预览会检查整份文件的币种，显示实际值和默认口径；其他字段在确认导入时校验。

### 结果解释

| 结果 | 条件 |
| --- | --- |
| 金额一致 | 两侧均存在，预计净额与账单净额相等，且没有重复业务键或重复流水 |
| 金额不一致 | 两侧均存在，但净额不同 |
| 仅业务单 | 订单只在业务单中出现，即使金额为零也保留该异常 |
| 仅支付账单 | 订单只在支付账单中出现 |
| 重复业务单 | 同渠道同订单存在多行业务单 |
| 重复流水 | 同渠道同流水号出现多次，跨订单重复时涉及的订单都提示 |

重复行不会被静默去重，合计含重复源行，须核查后撤销错误文件或替换为正确文件。同一订单可以同时有多种异常。金额一致只表示本工具声明口径下一致，不代表资金已经结算、到账或财务确认。

首版不支持直接导入微信或支付宝原始账单、不自动拉账、不调用支付接口，也不处理手续费、提现、分账、多币种、跨期归属或任意异构表自动匹配。这些需要实际使用方的规则和样例，再分别开发适配。

## 数据保存与备份

默认数据文件为项目目录下的 `data/ledgerdesk.sqlite3`。保存标准化的导入记录和原文件 SHA-256，不复制保存上传文件的完整原始字节；原 CSV 请自行保管。源文件的其他未映射列不会存储。

每次核查保存输入版本和结果。源数据追加后，旧结果标记为待重新核对；此时不能备注或导出。重新核对后，证据发生变化的差异回到“待处理”，证据未变的记录保留原处理状态。相同输入再次核对复用原结果。主列表分页展示最新结果摘要；点击查看后才读取单个订单完整源行。历史详情和差异也分页，版本变化时旧页会提示刷新，避免混合不同运行。详细接口与数据边界见 [大批次查询与版本契约](docs/PAGINATION.md)。

0.6.0 使用数据库 schema v6。打开旧库时先创建唯一备份，再在事务中建立并回填结果摘要索引；原始结果、源行和备注不修改，失败回滚。支持既有 v1～v5 升级，高版本库拒绝打开。旧库没有保存的原渠道和处理快照保持未知。升级前先停止所有使用该目录的旧服务。请勿用旧版程序打开升级后的库；回退时停止服务，把升级前备份复制到新的数据目录。

导入文件可以在批次中撤销，或用新文件原子替换。撤销/替换前自动创建数据库备份，旧文件和源行继续保留在操作记录与历史核对中，但不再参与新的核对；完成操作后必须重新核对。替换必须填写原因，文件失败或备份失败时旧文件保持有效。重新核对会把新增或变化的异常置为待处理，证据未变化的处理状态继续保留。结果页可按异常类型和处理状态筛选，“导出全部”导出当前运行的全部记录；“导出当前筛选”同时包含顶部分类、异常类型、处理状态和搜索条件。两种导出都校验页面显示的运行版本，过期链接需要刷新。

映射模板支持保存、同名更新修订、复制、删除，以及 JSON 文件导入和导出。模板更新不会修改已经导入的数据。在导入对话框中，渠道别名按“原渠道 = 统一渠道”逐行填写，选择模板后仍可检查修改。相同文件的映射或别名变化需要使用替换文件，不会静默跳过。

批次支持最多 20 个标签、归档与恢复。列表可以按进行中/已归档筛选，并搜索名称、说明和标签。归档保留全部数据、核对与备注，暂停导入、核对和处理，恢复后继续操作。

历史处理快照只代表每次运行发生时的状态。0.4 之前没有记录快照的运行显示“未记录”；后来保存的备注不会改写旧快照。主列表和导出仍使用当前处理状态。

点击“数据管理”，可创建并校验手动备份、查看最近 100 份备份、只读检查数据库、导出不含订单和本机路径的诊断报告，以及把备份恢复到全新目录。恢复不切换当前工作空间，也不覆盖已有目录。详细规则见 [本地数据保护与恢复](docs/DATA_MANAGEMENT.md)。

创建独立备份文件：

```powershell
python -m ledgerdesk --backup .\backups\ledgerdesk-20261018.sqlite3
```

备份使用 SQLite 在线备份接口，可以在服务运行时执行；已有同名备份不会覆盖。手动恢复使用 CLI，目标必须是尚不存在的新目录：

```powershell
python -m ledgerdesk --restore .\backups\ledgerdesk-20261018.sqlite3 --restore-to .\restored-data
python -m ledgerdesk --data-dir .\restored-data --port 8766 --open
```

`.gitignore` 已排除默认数据、备份、日志及导出文件。测试会生成临时数据库并自动清理。默认数据目录中的两份自测记录是本次浏览器验收产生的，说明中已标明为合成数据。批次详情中的有效文件旁可执行替换或撤销，已撤销文件会单独保留历史信息。

诊断命令只读检查指定数据库，不启动服务，不创建缺失的数据库。检查不通过时退出码为 1：

```powershell
python -m ledgerdesk --diagnose
```

备份包含全部业务内容；导出的诊断报告只有版本、完整性和数量。数据库、备份、恢复目录和本机报告均不进入源码发布包。

## 配置

无需配置即可使用默认端口与数据目录。可复制 `config.example.json` 为本机 `config.local.json`，然后：

```powershell
python -m ledgerdesk --config config.local.json --check-config
python -m ledgerdesk --config config.local.json
python -m ledgerdesk --config config.local.json --port 8766 --no-open
```

配置相对路径以配置文件所在目录为基准，命令行参数优先；配置检查不会创建数据库。`config.local.json` 已加入忽略规则。详细模块、数据及 API 契约见 [架构说明](docs/ARCHITECTURE.md)。

## 验证与工程

```powershell
python -m unittest discover -s tests -v
node --check ledgerdesk/static/app.js
node --check ledgerdesk/static/data.js
node --check ledgerdesk/static/results.js
python scripts/build_release.py
python scripts/verify_release.py
```

第一条只需 Python；第二条是开发者可选的 JavaScript 语法检查，运行产品不需要 Node.js。

核心模块：

```text
ledgerdesk/imports.py       CSV 校验、字段映射和金额解析
ledgerdesk/store.py         兼容入口、批次与导入事务
ledgerdesk/domain/         金额、映射、核对、筛选和历史差异
ledgerdesk/application/    核对用例、CSV 报告和本地数据管理
ledgerdesk/persistence/    迁移、连接、备份、模板与运行仓储
ledgerdesk/server.py        本地 HTTP/API、报告导出和请求检查
ledgerdesk/static/          不依赖打包工具的操作界面
samples/                   明确标记的合成输入
tests/                    业务、HTTP、可靠性回归和旧库 schema fixture
docs/                      产品边界、版本记录与真实反馈收集模板
```

仓库按实际工程需求组织，不为凑文件数量拆分代码。未来用于命题前，需要真实交付、维护问题和脱敏复现资料，并按届时规则确认来源资格。

从当前 61 个文件扩展至约 300 个文件的七阶段路线、功能验收和规模预算见 [docs/PROJECT_PLAN.md](docs/PROJECT_PLAN.md)。下一阶段为批量处理、处理冲突检查和操作记录查询；文件数量服从实际职责。
