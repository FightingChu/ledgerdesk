# LedgerDesk 本地账目核查工具

LedgerDesk 将业务单中的预计净到账，与支付账单中的收款减退款逐单比较，帮助定位金额差异、单边缺失、重复业务单和重复流水。它在本机浏览器运行，使用本地 SQLite 保存批次、导入记录、文件指纹、核查结果和人工备注。

**当前状态：0.3.0 个人验证版。尚无真实客户、付费交付或生产使用记录。附带数据均为合成样例。** 本项目可以用于验证产品流程，当前状态不满足此前命题项目对真实客户或生产来源的要求。

## 启动

Windows 双击当前目录的 `start.cmd`。已安装 Python 3.10 以上即可，不需要安装第三方包、数据库服务、Node.js、域名或服务器。启动后会打开浏览器；保持终端窗口运行。已有同端口且使用相同数据目录的 LedgerDesk 时，再次双击会打开现有页面。不同数据目录会提示冲突，请换端口；0.1.0 旧服务需先停止后再启动。

也可以在项目目录的 PowerShell 中执行：

```powershell
python -m ledgerdesk --open
```

默认地址是 `http://127.0.0.1:8765`。按 Ctrl+C 停止，已提交的数据不会随窗口关闭消失。端口被其他程序占用时：

```powershell
python -m ledgerdesk --port 8766 --open
```

服务固定绑定 `127.0.0.1`，首版面向单人本机使用。界面没有远程账户或多人权限管理，不能直接当作公网服务部署。

## 第一次体验

1. 点击“创建样例批次”。系统导入附带的合成数据，生成 7 个订单分组，其中 2 个金额一致、5 个有差异。
2. 使用“待核查差异 / 全部记录 / 金额一致”和订单号搜索筛选记录。
3. 点击“查看”，核对源文件名、CSV 行号、收款和退款记录。
4. 填写处理备注。标记“已处理”时必须填写依据；人工状态不会将金额差异改成金额一致。
5. 点击“导出核查报告”，下载带 UTF-8 BOM 的 CSV。合成样例会在导出中明确标注。

创建自己的核查批次时，分别上传业务单与支付账单，确认每个字段对应的 CSV 列，再执行核对。导入预览显示前五行；确认导入会校验整份文件。数据有错误时整份不写入，页面列出错误行。

## 输入格式和业务口径

首版处理**标准逗号分隔 CSV**，支持 UTF-8、UTF-8 BOM、GB18030。单文件不超过 5 MiB、10000 行。可以在一个批次中导入多份文件。同一批次、同一数据侧、相同原始字节的文件只导入一次，重命名文件不会绕过此检查。相同文件用不同映射再次导入会被拒绝，纠正映射请创建新批次。

业务单格式：

```csv
order_id,amount,channel
000012,80.00,wechat
```

`amount` 是该订单**预期收到的净额**：扣除预计退款，不扣支付手续费。首版只接受非负数；一组 `(channel, order_id)` 应只有一行业务单。订单号按字符串处理，保留前导零。

支付账单格式：

```csv
order_id,transaction_id,amount,event_type,channel
000012,P0001,100.00,sale,wechat
000012,R0001,20.00,refund,wechat
```

`sale` 表示收款，`refund` 表示退款，两者金额都填写正数。兼容中文“收款 / 支付 / 退款”。每个渠道内的 `transaction_id` 应唯一，退款须使用不同的退款流水号。同订单多次合法收款或退款允许合并。

核查按 `(channel, order_id)` 精确匹配，渠道和订单号去除首尾空白后保留大小写。`wechat` 和 `微信` 是不同渠道值，导入前需统一命名。计算为：

```text
账单净额 = 该订单收款合计 - 退款合计
差额 = 账单净额 - 业务单预计净到账
```

所有金额仅接受人民币元，最多两位小数，内部转成整数分计算。不接受负数输入、千分位、科学计数法和超过 100 亿元的单行金额。零金额保留。自动识别 `currency`、`currency_code`（不区分大小写）及 `币种`、`货币`、`货币种类` 列，只接受 CNY、RMB、人民币（英文值不区分大小写）。多个币种列须在每一行表达相同币种，CNY 与 RMB 视为等价；空白、未知币种、非人民币或冲突列会拒绝整份导入。没有币种列时按本工具约定视为人民币，不自动汇兑。预览会检查整份文件的币种，显示实际值和默认口径；其他字段在确认导入时校验。

### 结果解释

| 结果 | 条件 |
| --- | --- |
| 金额一致 | 两侧均存在，预计净额与账单净额相等，且没有重复业务键或重复流水 |
| 金额不一致 | 两侧均存在，但净额不同 |
| 仅业务单 | 订单只在业务单中出现，即使金额为零也保留该异常 |
| 仅支付账单 | 订单只在支付账单中出现 |
| 重复业务单 | 同渠道同订单存在多行业务单 |
| 重复流水 | 同渠道同流水号出现多次，跨订单重复时涉及的订单都提示 |

重复行不会被静默去重，合计含重复源行，须核查后用正确文件建立新批次。同一订单可以同时有多种异常。金额一致只表示本工具声明口径下一致，不代表资金已经结算、到账或财务确认。

首版不支持直接导入微信或支付宝原始账单、不自动拉账、不调用支付接口，也不处理手续费、提现、分账、多币种、跨期归属或任意异构表自动匹配。这些需要实际使用方的规则和样例，再分别开发适配。

## 数据保存与备份

默认数据文件为项目目录下的 `data/ledgerdesk.sqlite3`。保存标准化的导入记录和原文件 SHA-256，不复制保存上传文件的完整原始字节；原 CSV 请自行保管。源文件的其他未映射列不会存储。

每次核查保存输入版本和结果。源数据追加后，旧结果标记为待重新核对；此时不能备注或导出。重新核对后，证据发生变化的差异回到“待处理”，证据未变的记录保留原处理状态。相同输入再次核对复用原结果。当前界面展示最新结果，数据库保留历史核对记录。

0.3.0 使用数据库 schema v4。首次打开 0.1.0 的 v1 库或 0.1.1 的 v2 库时，会在数据库旁创建升级前备份，然后在同一事务内增加导入币种核验、有效文件、撤销/替换链和输入版本字段。备份失败会停止升级，迁移失败会回滚；高于支持版本的数据库会拒绝打开。旧记录保留原核对结果及备注，界面提示币种未重新核验，因为旧版未保存原始币种列。需要复核时请使用原 CSV；发现非人民币请新建批次重新导入。请勿用旧版打开升级后的库；回退时使用升级前备份并复制到新的数据目录。

导入文件可以在批次中撤销，或用新文件原子替换。撤销/替换前自动创建数据库备份，旧文件和源行继续保留在操作记录与历史核对中，但不再参与新的核对；完成操作后必须重新核对。替换必须填写原因，文件失败或备份失败时旧文件保持有效。重新核对会把新增或变化的异常置为待处理，证据未变化的处理状态继续保留。结果页可按异常类型和处理状态筛选，导出链接始终导出当前核对版本的全部记录。

0.3.0 增加映射模板和渠道别名。模板保存字段映射及别名 JSON，导入前可以复用并检查；例如 `{"微信":"wechat","支付宝":"alipay"}`。批次详情保存每次核对历史，可以比较两次运行中新增、消失和变化的订单。导出支持全部记录或当前异常/处理状态筛选。

创建独立备份文件：

```powershell
python -m ledgerdesk --backup .\backups\ledgerdesk-20261018.sqlite3
```

备份使用 SQLite 在线备份接口，可以在服务运行时执行；已有同名备份不会覆盖。恢复时先停止服务，将备份复制到一个新的数据目录并命名为 `ledgerdesk.sqlite3`，然后：

```powershell
python -m ledgerdesk --data-dir .\restored-data --port 8766 --open
```

`.gitignore` 已排除默认数据、备份、日志及导出文件。测试会生成临时数据库并自动清理。默认数据目录中的两份自测记录是本次浏览器验收产生的，说明中已标明为合成数据。批次详情中的有效文件旁可执行替换或撤销，已撤销文件会单独保留历史信息。

## 验证与工程

```powershell
python -m unittest discover -s tests -v
node --check ledgerdesk/static/app.js
```

第一条只需 Python；第二条是开发者可选的 JavaScript 语法检查，运行产品不需要 Node.js。

核心模块：

```text
ledgerdesk/imports.py       CSV 校验、字段映射和金额解析
ledgerdesk/store.py         导入事务、核对规则、人工处理、持久化和备份
ledgerdesk/server.py        本地 HTTP/API、报告导出和请求检查
ledgerdesk/static/          不依赖打包工具的操作界面
samples/                   明确标记的合成输入
tests/                    业务、HTTP、可靠性回归和旧库 schema fixture
docs/                      产品边界、版本记录与真实反馈收集模板
```

仓库按实际工程需求组织，不为凑文件数量拆分代码。未来用于命题前，需要真实交付、维护问题和脱敏复现资料，并按届时规则确认来源资格。

产品扩展路线、架构拆分、版本目标和文件规模预算见 [docs/PROJECT_PLAN.md](docs/PROJECT_PLAN.md)。文件数量服从真实功能、测试和文档，不单独追求数字。

源码发布包通过 `python scripts/build_release.py` 生成。公开仓库使用 MIT License，并通过 GitHub Actions 在 Python 3.10、3.12 上运行测试和发布包校验。版本统一读取 `ledgerdesk/__init__.py`；页面和 CLI 使用相同版本定义，包元数据采用动态版本。发布脚本仅打包显式清单中的文件，不递归收集 CSV 或临时脚本；新增发布文件需要更新清单。ZIP 默认使用构建时的 UTC 时间，可设置 `SOURCE_DATE_EPOCH` 以复现同一时间戳。
