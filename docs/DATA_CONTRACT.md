# 数据身份与精度

业务键是去除首尾空白后的渠道与字符串订单号，保留大小写与前导零。支付流水号在同一渠道内应唯一，跨渠道同号可以独立存在。金额使用整数分，不做汇兑。

输入身份包含引擎版本、输入修订、有效文件 ID/哈希/映射/别名。显式选择规则时加入不可变规则快照；没有选择规则的旧批次保持原身份构造。

源证据指纹包含导入、行号、业务键、事件类型和金额；显式规则也参与证据身份。证据变化生成新一代，避免恢复旧文件时复活很久之前的已处理状态。

运行及其结果、规则快照和标准化源行不可变。当前备注按批次、核查键与证据指纹保存整数处理版本；历史只读状态来自当时快照，缺失时未知。

结果摘要、整数金额表和源行表是原始结果 JSON 的查询投影，必须在核对事务内一起写入。旧库回填不修改原 JSON。投影缺失应诊断和恢复，不能猜造证据。

备份为一个已提交 SQLite 快照。恢复保留备份原 schema，正常打开恢复副本时才进行升级。报告读快照冻结该次导出期间的实时备注。
