# 本地数据保护与恢复

0.7.0 使用 schema v7，打开旧库前先备份；v6 → v7 事务新增处理版本与审计索引，更早版本同时回填结果摘要索引。备份和恢复本身不迁移源文件。所有操作使用 Python 标准库和本机 SQLite，无需账户或远程服务。

## 在页面中使用

打开“数据管理”，可以执行：

1. **创建并校验备份**：使用 SQLite 在线备份接口复制已提交的数据，再检查备份结构、完整性和外键。备份的数量摘要与复制内容来自同一个数据库快照。
2. **检查当前数据库**：只读检查 schema、已知表及必需字段、SQLite 完整性和外键，显示批次、源行、运行、备注等记录数量。
3. **校验备份**：重新检查所选文件并计算其 SHA-256，便于记录和比对文件。
4. **恢复到新目录**：先检查备份，再输入一个尚不存在的目录名称，确认后复制并校验恢复数据。当前工作空间和当前服务保持原样。

恢复完成后，页面给出 PowerShell 启动命令，使用相邻端口打开新工作空间。恢复不会替你切换当前服务、结束原服务或覆盖旧数据库。

手动备份位于当前数据目录下的 `backups/`，列表显示最近 100 份；页面会显示实际路径。升级、撤销和替换生成的自动备份仍位于数据库旁，不混入手动列表。手动备份没有自动删除或保留期限，磁盘管理由使用者决定。

恢复文件位于当前数据目录下的 `restored/<新目录名称>/ledgerdesk.sqlite3`。名称只接受 1～64 个英文字母、数字、下划线或短横线，以字母或数字开头；拒绝路径穿越、绝对路径、符号链接目录和 Windows 保留名称。

## 命令行

创建一个指定位置的新备份文件：

```powershell
python -m ledgerdesk --backup .\backups\manual.sqlite3
```

输出只读诊断报告，不启动 HTTP 服务：

```powershell
python -m ledgerdesk --diagnose
python -m ledgerdesk --data-dir .\other-data --diagnose
```

恢复到一个全新数据目录，并在另一个端口打开：

```powershell
python -m ledgerdesk --restore .\backups\manual.sqlite3 --restore-to .\recovered-data
python -m ledgerdesk --data-dir .\recovered-data --port 8766 --open
```

`--restore` 和 `--restore-to` 必须一起使用；备份、诊断和恢复是互斥操作，不能和 `--check-config` 混用。恢复不要求启动原工作空间，也不会因原数据目录不存在而创建一个空库。

恢复保留备份本来的 schema 版本。恢复 v1～v6 库时，直到用正常启动命令打开恢复副本，才按照已有规则先备份再升级到 v7；原备份不被迁移。

## 诊断报告

报告格式为 `ledgerdesk.database-diagnostics`、版本 1，仅包含：

- 应用版本、支持的 schema 和文件中的 schema；
- 数据库文件大小；
- 完整性检查结果、外键异常数量；
- 已知业务表的行数和 v6 及以后版本的结果摘要数量覆盖检查。

它不读取并返回订单号、备注、批次名称、CSV 文件名、渠道值或本机路径。页面可下载报告；CLI 的 JSON 输出也可以按需保存。备份文件本身包含全部数据库内容，应保存在本机受控位置，不能作为诊断报告公开提交。

状态含义：

| status | 含义 | CLI 退出码 |
| --- | --- | --- |
| `ok` | 支持的 LedgerDesk schema，结构、完整性和外键检查通过 | 0 |
| `missing` | 指定源文件不存在；不会创建文件或数据目录 | 1 |
| `invalid` | 文件损坏、结构不符、未初始化或存在完整性/外键问题 | 1 |
| `unsupported` | schema 高于当前支持版本，拒绝恢复或自动修改 | 1 |

检查通过表示数据库结构可读取和恢复，不代表账单来源、金额口径或人工处理结论已经正确。SHA-256 标识所检查文件的内容，不是来源认证。

## 恢复与失败规则

- 任何已经存在的恢复目录都会被拒绝，包括空目录。
- 数据先复制到新目录中的唯一临时文件，校验通过后才发布为 `ledgerdesk.sqlite3`。
- 发布优先使用不覆盖目标的硬链接；文件系统不支持时使用独占创建方式复制。
- 目标文件在恢复过程中由其他进程创建时，恢复会失败并保留该文件。
- 失败只清理本次创建的临时或目标文件，不递归删除目录、不清理原库、不删除备份。
- 新备份被保存为不依赖 WAL 附属文件的独立 SQLite 文件，便于只读校验和恢复。

## 当前范围

本版没有远程备份、自动轮换、云同步和原地覆盖恢复。真实渠道适配仍等待明确版本的真实账单样例；本版的验证使用现有合成数据、故障注入和隔离工作空间。
