# 0.7 批量处理与操作记录

## 页面流程

在当前结果页勾选差异，或选择当前页全部可处理差异，再点击“批量处理”。每次最多 100 项，只支持“处理中”和“已处理”；已处理须填写依据。

共享备注会替换所选项原备注，确认前页面显示数量与替换说明。金额一致、归档、过期输入和历史结果均不可批量处理。翻页、改变筛选、搜索、刷新或切换批次时清空选择，不跨页隐含全选。

每项保存同时检查证据指纹和整数处理版本。任一项冲突或写入失败时，整批备注与审计回滚；冲突提示后刷新并重新选择。重复发送相同请求会因版本过期被拒绝，不会追加重复的成功记录。用户重新读取版本后可发起新的处理操作。

单项详情也检查运行与处理版本；冲突时保留本次输入供核对。“重新加载详情”会用最新状态和备注替换输入。人工处理不改变金额差额，也不重写历史运行的处理快照。

## 写入接口

路径以 `/api/batches/<批次ID>` 开头。POST 继续要求 JSON、本机会话 token 和允许的请求来源。

`POST /bulk-review`：

```json
{
  "run_id": "页面显示的运行ID",
  "items": [
    {"case_key": "核查键", "evidence_sha256": "证据指纹", "expected_revision": 0}
  ],
  "status": "in_progress",
  "note": "共享处理备注"
}
```

列表必须包含 1～100 项，核查键不重复。每项必须属于该批次的最新、未过期运行，并且是异常记录；`expected_revision` 必须为非负整数，布尔值不接受。

成功响应包含 `saved`、`count`、`run_id`、`operation_id` 和 `items`。每条成功项返回 `case_key` 和新的 `review_revision`。`operation_id` 关联同次操作的逐项审计与汇总；它由服务端产生，不是请求幂等键。

`POST /review` 保留单项字段 `case_key`、`evidence_sha256`、`status`、`note`，从 0.7 起 HTTP 调用须额外提供 `run_id` 和 `expected_revision`。单项仍可设置为“待处理”。旧 HTTP 客户端需要从结果摘要或详情读取版本后更新请求。

Python `Store.review(batch_id, case_key, evidence_hash, status, note)` 保留兼容；省略两个版本参数时仍检查证据与最新输入，但采用最后写入生效语义。新调用者应同时提供 `run_id`、`expected_revision`。`Store.bulk_review` 必须指定版本。

错误仍使用 HTTP 400 及稳定错误码：

| 错误码 | 含义 |
| --- | --- |
| `review_conflict` | 任一处理版本已变化，整批未保存 |
| `stale_result` | 输入、运行或证据已变化，整批未保存 |
| `batch_archived` | 批次已归档 |
| `invalid_selection` | 数量、重复键或金额一致项不符合要求 |
| `invalid_revision` | 缺少或非法处理版本 |
| `invalid_input` | 状态、备注或其他字段无效 |

## 读取版本与迁移

最新结果摘要和当前订单详情增加 `review_revision`：尚无处理记录为 0，首次保存为 1，以后每次成功保存递增。版本按批次、核查键和证据指纹隔离，不依赖秒级时间戳。历史分页/详情的该字段为 `null`，只读历史不提供可提交的版本。

schema v7 为 `reviews` 添加整数 `revision`，旧记录初始化为 1，并为审计增加批次与类型查询索引。迁移前备份，列、索引和版本号在同一事务中提交；原列、源行、结果 JSON、备注、旧审计和快照不改写。

## 操作记录分页

`GET /audit?page=1&page_size=25&action=all` 返回批次操作记录；每页允许 1～100 项，按事件 ID 倒序。可按创建、设置、导入、撤销、替换、核对、单项变更或批量汇总筛选。

响应包含 `items`、`total`、`page`、`page_size`、`total_pages`、`until_id` 和 `actions`。`items.payload` 为 JSON 对象；旧批次详情的最近 50 条审计格式继续保留，勿混用两者。

首次请求返回当前事件上限 `until_id`，后续页携带该值；同一查询过程中到达的新事件不会挤动旧页。刷新或切换类型时重新获取上限。单次总数和页面共享一个只读事务，所有查询都限定批次。

新单项变更记录保存前后状态、备注和处理版本；批量处理额外保存数量、目标状态、依据与操作编号。旧事件没有保存的前态不补造。审计用于本机追溯，不宣称具备防篡改或多用户身份认证能力。
