# 当前分页与版本契约

0.13在原有结果分页上增加单订单源行分页和有界历史比较。旧批量接口仍保留兼容；新页面只使用摘要、info与evidence接口。详细新入口见 [API参考](API_REFERENCE.md)。

## 页面行为

- 默认每页 50 项，可选择 25、50、100；服务端每页上限为 100。
- 顶部分类、异常类型、处理状态和搜索均在服务端组合筛选，改变条件后回到第一页。
- 搜索输入延迟 200ms 发起请求，新请求会淘汰较早的响应，避免快速切换条件后显示旧页面。
- 点击“查看”先读取摘要，source和duplicate源证据分别按25条分页，不反序列化整条源数组。
- 保存备注后刷新列表，重新计算筛选总数；筛选后的空批次或空结果仍显示可用的页状态。
- 翻页和单条详情携带页面显示的运行 ID。若另一页面已经重跑核对，旧请求返回 `stale_result`，当前页清空并提示“刷新结果”。不会自动混用两次运行。
- 仅追加输入但尚未重跑时，可查看旧运行的分页结果，页面显示过期状态，继续禁止备注和导出。
- 历史页只读展示运行时处理快照，点击源行按钮按需读取旧证据。历史列表每页 50 项；差异比较每页最多 50 项，不下载完整源行数组。

处理状态为实时查询值，不跨多次分页请求冻结。单次请求中的总数与当前页使用同一个 SQLite 只读事务；另一页面改动处理状态后，后续请求会显示新的筛选总数。

## 接口

以下路径均以 `/api/batches/<批次ID>` 开头：

| 路径 | 行为 |
| --- | --- |
| `/overview` | 批次、文件、最近运行、操作记录和历史目录，不含 `results` |
| `/results?page=1&page_size=50&run_id=...` | 当前运行的结果摘要页，不含 `rows` 或 `duplicate_rows` |
| `/cases/<case_key>?run_id=...` | 兼容接口：当前运行的一条结果及完整源证据 |
| `/cases/<case_key>/info?run_id=...` | 当前详情摘要，不含源数组 |
| `/cases/<case_key>/evidence?run_id=...&kind=source&page=1&page_size=25` | 当前源行页，kind也可为duplicate |
| `/runs/<run_id>/results?page=1&page_size=50` | 指定历史运行的摘要页，只读 |
| `/runs/<run_id>/cases/<case_key>` | 指定历史运行的一条源证据，只读 |
| `/compare-page?from=...&to=...&page=1&page_size=50` | 两次历史运行的差异计数及当前页差异摘要 |
| `/export?run_id=...` | 全部筛选结果 CSV，不受当前页码和每页条数限制 |

当前结果页和导出使用与 0.4 相同的 `group`、`reason`、`status`、`q` 筛选。搜索按去空白后的小写文本进行字面子串匹配，`%` 和 `_` 不被解释为 SQL 通配符。重复参数、非法页码和超出上限的页容量会被拒绝；请求超出实际末页的页码会被归一到末页。

摘要页返回 `run_id`、`items`、`page`、`page_size`、`total`、`total_pages`、`stale`、`read_only`。0.7 当前摘要增加 `review_revision`（无记录为 0，历史为 null）。每条摘要保留核查键、金额、异常、证据指纹和处理状态，增加 `source_count`、`duplicate_count`，不带源行数组。

旧的批次整批详情、历史整批详情和整批比较 API 为既有调用者保留。新页面不使用这些批量接口；已有 `Store.detail`、`run_detail` 和 `compare_runs` 调用保持兼容。

## 存储和迁移

schema v6 增加 `result_lookup`：按运行和核查键保存紧凑结果摘要、顺序、搜索文本、异常标记和处理快照。结果表的原始 JSON 不修改，源行与历史证据继续保留。

- 迁移前在线备份；新增表、回填和版本号更新在同一事务内完成，失败回滚。
- 回填旧运行时保留原结果顺序，缺少旧处理快照时仍然显示“未记录”。
- 新运行在同一事务中同时写入结果与查询摘要，处理状态通过原备注表实时关联。
- 页总数通过 SQL `COUNT` 获取，摘要通过 `LIMIT / OFFSET` 读取；列表不反序列化每个订单的大型源行 JSON。
- 完整导出按游标遍历所有匹配摘要，页面导出改为分块CSV/HTML并保持同一读快照；旧export_csv兼容函数仍在内存组装。
- 历史比较由SQL合并两侧紧凑摘要，逐条计算差异，只保留所请求页与末页缓冲；耗时随运行规模增长，不加载完整源数组。
- 只读诊断增加结果与摘要数量覆盖检查，缺失摘要行会被识别为无效状态。

## 验证范围

合成回归包含 5001 个订单分组、分页无重复/遗漏、中文搜索和字面通配字符、实时备注筛选、并发修改后的单请求一致性、旧版本拒绝混页、历史源行、差异分页、完整筛选导出、v5 回填失败回滚与原数据保留。

这些验证用于本机工程验收，不代表真实渠道兼容性、客户验收或任意规模的性能承诺。0.7 已增加当前页批量处理与处理版本，见 [批量处理与操作记录](BULK_REVIEWS.md)；报表模板和统计图表仍待后续实现。
